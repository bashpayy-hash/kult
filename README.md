# Бөлек — пилот закрытого комьюнити в Алматы

**Бөлек** — по-казахски «отдельный, особый». До 12 ноября 2026 проект
назывался Shaqyru («шақыру», приглашение).

Участница (micro-аккаунт 1–3k) получает ужин или услугу в заведении и
публикует сторис с личной ссылкой. Подписчики бронируют по ссылке или
приходят и называют фразу «я от {имя}». Хостес отмечает, кто пришёл и на
какой чек. Админка считает главное: **сколько платящих гостей приводит один
визит участницы** (порог успеха пилота — 2).

План и схема БД — [`docs/PLAN.md`](docs/PLAN.md). Дизайн — [`DESIGN.md`](DESIGN.md).

| Страница | Для кого |
|---|---|
| `/` | Каталог: все места с фильтром по категориям, у каждого чек, часы, бонус и ближайшее свободное время |
| `/v/{заведение}` | Страница заведения: часы, план зала, выбор стола и времени, бронь |
| `/join` | Клуб: как это работает и две заявки — участница и заведение |
| `/{участница}/{заведение}` | Подписчики: то же, что `/v/…`, плюс «от кого» и фраза. Каждое открытие — клик |
| `/h/{токен}` | Хостес, без логина, с телефона |
| `/admin` | Админка по паролю |

Стек: Next.js 16 (App Router, Server Actions), Postgres (Netlify
Database), Netlify Blobs для файлов, Tailwind 4, хостинг Netlify. Шрифт —
один, Inter Tight (как на iitaly.net), в разных начертаниях. Визуальный язык — Design DNA пяти
обложек годовых отчётов (`design/dna/annual-reports.json`); картинки из
Higgsfield (`design/illustrations/plates-2026-11-12.json`): у каждой
категории своя обложка-коллаж, пока заведение не загрузило своё фото.

## 1. Развернуть

Живой сайт: **https://shaqyru-7ol3.netlify.app** (Netlify, проект
`shaqyru-7ol3` в команде владельца).

### 1.1 Netlify

Всё уже настроено, ниже — что и где, чтобы повторить или поправить.

- **База — Netlify Database** (Postgres). Её создаёт сам Netlify, потому
  что в зависимостях есть `@netlify/database`; строку подключения
  приложение берёт из `NETLIFY_DB_URL`. Миграции лежат в
  `netlify/database/migrations/`, и каждый деплой применяет новые сам,
  до публикации; ошибка в миграции останавливает деплой.
  Уже применённую миграцию **нельзя менять или удалять** — только
  добавлять новую со следующим номером.
- **Файлы — Netlify Blobs** (хранилище `uploads`): фото и логотипы
  заведений, скрины сторис. Сайт отдаёт их сам: фото по
  `/uploads/venue-photos/…`, скрины только админке по `/admin/files/…`.
- **Next.js** собирается адаптером `@netlify/plugin-nextjs` из
  `netlify.toml`.
- **Переменные** (Project configuration → Environment variables):

  | Переменная | Значение |
  |---|---|
  | `ADMIN_PASSWORD` | пароль админки, длинный |
  | `SESSION_SECRET` | `openssl rand -hex 32` |
  | `NEXT_PUBLIC_SITE_URL` | адрес сайта без слеша в конце: `https://shaqyru-7ol3.netlify.app` |
  | `STORAGE_BACKEND` | `blobs` |
  | `PILOT_THRESHOLD` | `2` (необязательно) |
  | `NEXT_PUBLIC_OPERATOR_NAME` | юрлицо оператора данных для `/privacy` (необязательно) |
  | `NEXT_PUBLIC_CONTACT_EMAIL` | почта для запросов по данным (необязательно) |

  После смены переменной нужен новый деплой: значения подставляются при
  сборке. Смена `ADMIN_PASSWORD` или `SESSION_SECRET` разлогинивает всех.
- **Доступ**: основной адрес открыт всем, тестовые деплои — только после
  входа в Netlify.
- **Деплой**: загрузка кода через Netlify MCP или, если подключить
  репозиторий в Netlify (**Project configuration → Build & deploy →
  Link repository**), — сам на каждый пуш.

**Демо-данные.** Миграция `0005_demo_data.sql` заполнила пустую базу
выдуманными заведениями (Nomad Bar, Lotus Spa, Sora Bistro, Mono Coffee,
Atelier Nails, Pilates Loft), двумя участницами, бронями и визитами. Перед
запуском с настоящими заведениями — новая миграция, которая удаляет эти
строки по их id (сам файл `0005` не трогать). Демо-ссылка хостес:
`/h/demo-host-token-nomad-bar-0001`.

### 1.2 Другой хостинг

Подойдёт любой Postgres 15+ и любой хостинг Next.js: `DATABASE_URL`
вместо `NETLIFY_DB_URL`, миграции — `npm run db:migrate` (строка
подключения без пулера, порт 5432). Файлы — Supabase Storage:
`SUPABASE_URL` и ключ `service_role` (только на сервере, никогда в
`NEXT_PUBLIC_…`), бакеты `venue-photos` (public) и `story-proofs` (private)
создаст миграция `0002_storage.sql`. Для Vercel в репозитории есть
`vercel.json` (регион `fra1`, Франкфурт).

### 1.3 Локально

```bash
cp .env.example .env.local
```
Заполните `.env.local` (`DATABASE_URL` — локальный Postgres), затем:
```bash
npm run db:migrate
```
```bash
npm run dev
```
`db:migrate` применяет все миграции, включая демо-данные. `npm run db:seed`
стирает все строки и заливает демо заново — **только для локальной базы**.

Без хранилища в режиме разработки картинки сохраняются в `.uploads/`.
Для локального `next start` добавьте `STORAGE_LOCAL=1`.

Проверки перед PR:
```bash
npm run typecheck && npm run lint && npm run build
```

## 2. Завести заведение

1. **Админка → Заведения → Добавить заведение** (или одобрите заявку из
   **Заявки** — карточка создастся сама).
2. В карточке заведения:
   - **Фото для страницы гостей** — горизонтальное, 4:3. Большие фото
     сжимаются в браузере перед загрузкой. Пока фото нет, гости видят
     обложку категории (иллюстрация в духе 1950-х, не выдаётся за фото
     места). Там же **логотип** (квадрат).
   - **Готовность к каталогу** вверху карточки заведения показывает, чего
     не хватает: своё фото, логотип, описание на двух языках, план зала,
     бонус гостям, галочка «Показывать в каталоге». Это и есть список того,
     что запросить у заведения при подключении.
   - **Offers и perks → Добавить offer**:
     - «Что получает участница» — например, «Ужин на двоих и два коктейля»,
       и номинал в тенге;
     - «Perk для подписчиков» — бонус гостям, на русском и казахском;
     - «Условия» — их видят гости.
   - **Описание для гостей** на двух языках, адрес, Instagram.
   - **Город и точка на карте**: в 2ГИС или Google Картах правый клик по
     зданию → скопировать координаты → вставить в «Точка на карте»
     (например `43.2389, 76.9455`). Без точки место не появится на карте
     главной; ссылка «Маршрут в 2ГИС» тогда ищет по адресу.
   - **Карточка → часы работы**: открытие, закрытие (раньше открытия —
     значит после полуночи), шаг брони, на сколько минут держим стол.
     Галочки «Показывать в каталоге» и «Поднять выше в каталоге».
   - **План зала**: «Стол на 2 / на 4 / Большой стол» добавляют стол в
     центр, его перетаскивают на место, угол меняет размер, справа —
     номер и места от/до. «Подпись» — бар, кухня, вход, окна (не
     бронируются). Несколько залов — «Добавить зал». В конце «Сохранить
     план». Без столов бронь принимается просто по времени.

## 3. Завести участницу и выдать ей ссылку

1. **Заявки → Одобрить** (или **Участницы → Добавить участницу**). Только
   18+: база не примет возраст меньше.
2. Проверьте **Slug** — это часть ссылки: `/aruzhan/nomad-bar`. Имя в
   карточке видят подписчики: «Приглашение от Аружан», «я от Аружан».
3. **Ссылки → Новая ссылка**: участница, заведение, offer. Кодовая фраза
   по умолчанию — «я от {имя}» (по-казахски «мені {имя} жіберді»); можно
   задать свою.
4. **Скопировать ссылку** и отправить участнице: она ставит её стикером
   «Ссылка» в сторис.
5. После визита и сторис откройте пару (**Ссылки** → пара) →
   **Визиты участницы и сторис**:
   - визит обычно уже отметила хостес; если нет — **Добавить визит**;
   - **Добавить скрин сторис и просмотры**: скрин из статистики сторис и
     число просмотров. Просмотры можно уточнить позже.

## 4. Выдать ссылку хостес

1. **Заведения** → заведение → **Ссылка для хостес** → **Скопировать
   ссылку**.
2. Отправьте её хостес в личные сообщения. Логина нет: ссылка и есть ключ.
   Попросите добавить страницу на экран «Домой».
3. Что хостес делает на странице:
   - **Брони** на вчера, сегодня и завтра — с номером стола и пометкой
     «от {участница}» или «из каталога». День хостес — с 06:00 до 06:00:
     бронь на 01:00 видна в списке предыдущего вечера. Гость пришёл —
     **Пришли**, число гостей и сумма чека. Не пришёл — **Не пришли**;
   - **Гость без брони назвал фразу** — от кого, сколько гостей, чек;
   - **Визит участницы** — кто, когда, что получила (подставляется из offer);
   - **Отмечено за день** — ошибку можно удалить.
4. Ссылка утекла или хостес сменилась — **Выпустить новую**: старая
   перестанет работать сразу.

## 5. Как гость бронирует

С карточки каталога: тап по времени сразу открывает бронь с этим днём и
временем. На `/v/{заведение}` или по ссылке участницы: день → число гостей
→ время (занятые слоты зачёркнуты) → стол на плане или в списке под ним
(можно не выбирать: система посадит за самый маленький подходящий
свободный стол) → имя, телефон, согласие. Двойную бронь стола не пропустит база: даже если двое нажмут
одновременно, второй увидит «Этот стол только что заняли».

## 6. Дашборд и выгрузка

**Админка → Дашборд** — по каждой паре участница + заведение: визиты
участницы, просмотры сторис, клики (без ботов и превью ссылок), брони,
пришедшие гости, выручка, **гостей на визит**, **конверсия просмотров в
гостей**. Пары с результатом ≥ `PILOT_THRESHOLD` подсвечены зелёным.
**Скачать CSV** — та же таблица для Excel (разделитель `;`, UTF-8).

Как считается:
- **гости** — сумма «сколько гостей пришло» по броням и по фразе;
- **гостей на визит** = гости ÷ визиты участницы в этой паре;
- **конверсия** = гости ÷ просмотры сторис × 100%;
- **клики** — открытия страницы пары. Превью ссылок в Instagram, Telegram и
  WhatsApp помечаются ботами и не считаются. Открытия из админки
  считаются: проверяйте ссылку в приватном окне.

## Перед запуском

- [ ] Длинные `ADMIN_PASSWORD` и `SESSION_SECRET` в Netlify.
- [ ] Миграция, удаляющая демо-заведения и демо-участниц.
- [ ] `NEXT_PUBLIC_OPERATOR_NAME` и `NEXT_PUBLIC_CONTACT_EMAIL` — текст
      `/privacy` ссылается на них. Сам текст согласия стоит показать
      юристу.
- [ ] Казахские тексты интерфейса (`src/lib/i18n/kk.ts`) вычитать носителю.
- [ ] `npm run db:seed` на проде **не запускать**: он стирает все строки.
