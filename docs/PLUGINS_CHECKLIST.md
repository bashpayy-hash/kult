# Плагины для проверки жизнеспособности сайта

Памятка по опыту IITALY (ноябрь 2026). Три плагина и один метод. Для каждого сказано, что он проверяет, где полезен, где нет, как запустить и на что наткнулись.

## Коротко: что когда запускать

| Когда | Что | Зачем |
|---|---|---|
| После редизайна и перед запуском | **uxaudit** | Ловит технические и визуальные ошибки: перекрытия, мелкие кнопки, доступность, сломанные сценарии |
| Перед запуском и после крупных правок | **user-testing-agent** | Показывает, где новичок не понимает слова, теряется и бросает задачу |
| Перед тратами на рекламу | **market-mirror** | Сравнивает объявления, собирает возражения, оценивает цену. Даёт анкету для проверки на живых людях |
| Раз в 1–2 месяца, если на сайте факты и цифры | **Проверка фактов агентами** | Ищет устаревшие сроки, цены и правила по официальным источникам |

## 1. uxaudit — UX-аудит по каталогу проверок

- **Репозиторий:** https://github.com/gotalab/uxaudit
- **Установка:**
  ```bash
  claude plugin marketplace add gotalab/uxaudit
  ```
  ```bash
  claude plugin install uxaudit@gotalab-uxaudit
  ```
- **Запуск внутри Claude Code** (`<проект>` — имя проекта, `<адрес>` — адрес сайта):
  ```text
  /uxaudit:uxaudit <проект> --url <адрес> --viewports mobile,desktop
  ```

**Что проверяет.** Четыре уровня:
- L1/L2 — 21 автоматическая проверка скриптами: доступность, иерархия шрифтов, переполнение, признаки «ИИ-шаблона»;
- L3 — визуальные рубрики по скриншотам: иерархия, лишняя работа, единообразие;
- L4 — сценарии «понять → решить → сделать → восстановиться».

**Где полезен:**
- После редизайна, как регрессия: на IITALY нашёл, что кнопка чата закрывает «Купить», «+» в FAQ и ссылки в подвале.
- Мелкие зоны нажатия, перекрытия, переполнение на телефоне.
- Сломанные сценарии: на IITALY сравнение вузов на телефоне показывало один вуз из двух, а панель сравнения закрывала флажок.
- Чистая доступность (axe) и отсутствие шаблонного вида — хорошая проверка перед запуском.
- Удобно гонять повторно и сравнивать прогоны: было 1 из 7 сценариев без замечаний, стало 4 из 7.

**Где не полезен:**
- Правдивость текстов, цены, бизнес-смысл — он этого не видит.
- L3 и L4 субъективны. Если оценивает тот же агент, что делал правки, оценка не независимая. Лучше давать судье без контекста.
- Сценарии, которым нужен живой сервер (оплата, загрузка документов, чат), локально не проверяются.
- Встречаются ошибки самого инструмента: проверка `font-hierarchy` падала на странице без h2.

## 2. user-testing-agent — тест персонами

- **Репозиторий:** https://github.com/de6eling/user-testing-agent
- **Установка (macOS, Python 3.11+, Chrome):**
  ```bash
  git clone https://github.com/de6eling/user-testing-agent.git
  ```
  ```bash
  cd user-testing-agent && ./setup.sh
  ```
  Нужно расширение «Claude Code» для Chrome, вход в тот же аккаунт Claude. Дальше `claude`, внутри `/setup` (адрес сайта, персона, задача).
- **Запуск:** откройте сайт в Chrome, затем:
  ```bash
  claude --chrome --agent user-tester
  ```
  и внутри `/run-test`. Отчёт лежит в `runs/`.

**Что делает.** ИИ играет конкретного человека. У персоны есть черты: читает или пробегает глазами, ищет или листает, сколько терпит. Агент видит только экран, кликает по тому, что видит, и бросает задачу, когда кончается терпение. Каждое место, где он запутался, записывается как находка с типом и серьёзностью.

**Где полезен (на IITALY 6 прогонов дали 50 находок):**
- Непонятные слова и аббревиатуры: ISEE, DSU, CEnT-S, bando — их назвали все шесть персон.
- Не видно цену, кнопки «Цены» нет на виду, «бесплатно» против замка «с маршрутом» читается как подвох.
- Главный вопрос аудитории не находится: про «11 классов» не было ответа на главной.
- Где пользователь сдаётся и почему: рассказ от первого лица очень наглядный.
- Быстро и недорого: прогон занимает 1,5–8 минут, около 100–230 тыс. токенов.

**Где не полезен:**
- Это не статистика: персоны — модель, а не люди. Они грамотнее и терпеливее реальных и могут не заметить то, что заметит живой человек.
- Вход в аккаунт и оплату не проходит: логиниться нужно вручную заранее.
- Без расширения Chrome не работает. В облачных сессиях Claude Code его нет. На IITALY я повторил методику на своём браузере через Playwright: те же персоны, скриншоты, клики по координатам и бюджет терпения.
- Тестовый адрес может давать ложные находки. Сервер IITALY отвечал только основному домену, поэтому «проверка недоступна» и ошибка чата на тестовом адресе — не баги сайта.

**Совет.** 2–3 персоны из реальной аудитории (подросток с телефоном, родитель, человек на ноутбуке) по 1–2 главным задачам. Задачи ставьте как цель человека («узнать, сколько стоит»), а не как путь по сайту.

## 3. market-mirror — симуляция рынка и рекламы

- **Репозиторий:** https://github.com/DarkWorldCoder/market-mirror
- **Установка (Linux, macOS, WSL; нужны git, uv, Python 3.12; движок около 7 ГБ):**
  ```bash
  git clone https://github.com/DarkWorldCoder/market-mirror.git
  ```
  ```bash
  cd market-mirror && bash install.sh --configure
  ```
  Или как MCP-сервер:
  ```bash
  claude mcp add market-mirror -- uvx marketmirror
  ```
- **Модель.** Нужен провайдер: API-ключ или шлюз через уже выполненный вход в Claude Code / Codex / Gemini:
  ```bash
  ./mm gateway start claude
  ```
- **Запуск:**
  ```bash
  ./mm start
  ```
  ```bash
  ./mm cli quickstart --out scenarios/<проект>
  ```
  Затем поправьте `creatives.json` (свои объявления), `messages.txt` и в `market_test.json` поставьте `max_spend_usd`. После этого:
  ```bash
  ./mm cli market-test scenarios/<проект>/market_test.json
  ```

**Что делает.** Создаёт смоделированных покупателей нужной аудитории: возраст, город, бюджет, кому доверяют. Показывает им объявления в ленте Instagram и TikTok, проводит обсуждение и опрос. На выходе:
- вердикт «запускать / доработать / не запускать»;
- лучшее объявление;
- возражения и диапазон цены;
- план на 30 дней;
- анкета `real_check.md` для проверки на живых людях.

**Где полезен (на IITALY):**
- Сравнить объявления: пост «Без агентства» заметила половина, «Начни бесплатно» — никто.
- Собрать возражения заранее: доверие («слишком дёшево»), «что входит в цену».
- Получить готовые ответы на возражения и тексты для продаж.
- Анкета для 30 живых людей — практичный следующий шаг.

**Где не полезен:**
- Предсказывать продажи: на маленькой выборке (10 человек) он сам ставит доказательности D.
- Модели склонны к скепсису: «слишком хорошо, чтобы быть правдой» у них звучит чаще, чем у живой аудитории.
- Он верит тому, что вы ему описали. На IITALY он решил, что лендинг на английском, потому что язык в сценарии не указали. Пропишите в брифе язык, цену и что бесплатно.
- Тяжёлый (7 ГБ) и тратит лимиты модели: 10 человек — около 158 вызовов. Обязательно ставьте `max_spend_usd`.

**Подводный камень в закрытой сети.** Движок скачивает словарь токенизатора с `openaipublic.blob.core.windows.net`. Если сеть его не пускает, словарь `o200k_base` можно собрать из npm-пакета `js-tiktoken`: на IITALY он совпал с официальным по SHA-256. Его кладут в папку из `TIKTOKEN_CACHE_DIR`, а путь прописывают в `.env` движка.

## 4. Проверка фактов агентами (метод, не плагин)

**Что это.** 4–5 параллельных агентов, у каждого своя тема: поступление и документы, виза, деньги и стипендии, каталог (вузы и цены), общие тексты. Каждый сверяет факты из кода сайта с официальными источниками на сегодня и пишет таблицу: «где — что на сайте — актуально или нет — как правильно — источник с датой».

**Где полезен.** Сайты с цифрами, сроками и правилами, которые устаревают. На IITALY нашлись:
- закрывшееся окно приёма;
- нерабочая ссылка на конкурс;
- противоречия между строками сайта;
- опечатки в фактах.

**Где не полезен:**
- Если официальные сайты закрыты сетью окружения, агенты сверяют по выдержкам из поиска. Цифры по ним править опасно, их надо перепроверять по первоисточнику.
- Сам ничего не правит: решение по каждому факту за владельцем.

**Совет.** Разрешите в окружении домены официальных источников заранее. Правьте сразу только то, что устарело по дате или подтверждено первоисточником. Спорные цифры выносите в список «сверить».

## Что из этого реально помогло IITALY

1. **uxaudit** нашёл технические перекрытия и сломанные сценарии, всё исправлено.
2. **Тест персонами** показал главное для продаж: цена не видна, «бесплатно / платно» сбивает, жаргон.
3. **market-mirror** подсказал, какой пост пускать в рекламу первым, и задал вопросы для живых людей. Его прогноз продаж всерьёз не принимать.
4. **Проверка фактов** закрыла устаревшие сроки и ссылки.
